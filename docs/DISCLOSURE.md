# Experimental disclosure review for descriptive tables

This is the first bounded NIS-019 increment. It reviews one
`nis_descriptive_table` and produces a presentation table with primary and
complementary suppression. Regression tables, grouped comparisons, rendering
and serialization remain separate increments. The review assists a human
publication check; it does not certify a manuscript or approve annual support.

## Policy source

The current HCUP Nationwide Data Use Agreement guidance recorded in
[SOURCES.md](SOURCES.md) warns against publishing values 1–10 inclusive and
asks for review of hospital contributions. easyNIS does not embed that rule as
a default. The caller supplies every policy explicitly, and the result records
it. `suppress = c(1, 10)` reproduces the recorded DUA range. Saad and Ali must
review the policy and any applicable agreement before publication.

## Interface

`nis_disclosure_review(table, suppress, zero, min_hospitals, margins)`

- `table` is an experimental `nis_descriptive_table`. Other objects, including
  regression tables, are refused.
- `suppress` is a length-two whole-number vector `c(lower, upper)` with
  `1 <= lower <= upper`. A checked count inside this inclusive range is
  disclosive.
- `zero` is `"display"` or `"suppress"`. It applies to zero nonzero counts,
  zero binary zero-valued counts and zero suppressed margin sums. With
  `"display"`, such a zero is published as a legitimate zero. With
  `"suppress"`, it is disclosive. Missing counts use only the range: a field
  with no missing outcomes publishes no missing cell.
- `min_hospitals` is a positive whole number. A checked discharge group drawn
  from fewer contributing hospitals is disclosive.
- `margins` is a list, possibly empty, of additive relations. Each relation is
  a list with exactly a `total` row ID and a `parts` vector of distinct row IDs.
  It declares that the published rows satisfy total = sum(parts).

## Checked counts

Counts come from the unweighted included discharges retained in each row's
`nis_estimate`. They never use weighted estimates, so a large weighted total
generated by a small raw cell is still disclosive. Every row checks:

- `included`: discharges with an observed outcome. It is published as
  `unweighted_n`.
- `missing`: discharges excluded for a missing outcome. Rows on different
  fields can expose this count by differencing their `unweighted_n` values.
- `nonzero`: included discharges with a nonzero outcome. A total or mean
  reveals a sum over these discharges.

A field is binary when it is logical or every included value is zero or one.
For binary fields, `zero_valued` (included minus nonzero) is also checked
because a proportion, mean or total and its `unweighted_n` reveal the
complement. Nonzero and zero-valued groups also have their contributing
hospital counts checked when the group is nonempty. Hospitals are distinct
native first-level cluster identifiers, so pooled reused IDs remain distinct
by year.

A row with any disclosive check is a primary suppression. Its reasons list the
failed checks.

## Margins and complementary suppression

Each margin compares counts on one additive scale: binary rows contribute
their nonzero count and other rows contribute their included count. The call
fails unless total = sum(parts) holds exactly in those raw counts, because an
incorrect declaration would invalidate the review.

Within a margin, a single suppressed row is recoverable from the others. When
the total is published, the sum of the suppressed parts is also recoverable and
must not be disclosive. The review therefore repeats until, for every margin
that has a published row, either nothing is suppressed, or at least two rows
are suppressed and (when the total is published) their summed count passes the
range and zero checks. Each repair suppresses the published member with the
smallest margin count, breaking ties by table order. This greedy procedure is
conservative but not minimal. It covers only declared relations; undeclared
arithmetic relations, external publications and other tables remain the
reviewer's responsibility.

## Result

The result is a `nis_disclosure_review` list:

- `presentation`: the only export candidate. It contains `id`, `label`,
  `statistic`, `unit`, `estimand`, `estimate`, `se`, `lower`, `upper`, `df`,
  `confidence`, `unweighted_n` and `disclosure_status`. Status is `shown`,
  `suppressed_primary` or `suppressed_complementary`. Suppressed rows have
  `NA` estimate, SE, interval and count. Shown values are identical to the
  numeric table. Missing counts, supplied counts, weighted denominators and
  hospital counts are not columns, and the data frame carries no extra
  attributes.
- `audit`: internal counts, hospital counts, margin counts and reasons. It
  contains raw small counts and must stay local.
- `table`: the unchanged input table, also internal.
- `provenance`: the policy, canonical margins, rule source, procedure and
  scope `experimental_disclosure_review`, with `analysis_ready = FALSE`.

## Acceptance cases

Verification must use the installed public API on invented data. Cases cover
counts 0, 1, 9, 10 and 11 under the recorded range with both zero policies, a
large weighted total from three raw discharges, a single contributing hospital,
binary complements, missing-count differencing, margin recovery of one
suppressed part, a small summed pair forcing a third suppression, total
suppression, declaration and arithmetic failures, pooled reused hospital IDs,
exact preservation of shown values and absence of hidden raw fields.
